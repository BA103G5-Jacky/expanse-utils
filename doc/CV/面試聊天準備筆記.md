# 5. REST API 設計

在設計 REST API 時，我通常會先從 resource 的角度思考，例如 report、user 或 emission 這類資源。

再搭配 HTTP method，例如：

- GET
- POST
- PUT
- DELETE

另外也會注意 API 命名的一致性，以及 request / response 結構清楚。

如果查詢條件比較多，也會使用 query parameters，例如 filter 或 pagination。

範例：

GET /reports?year=2024&page=1&size=20

# 6. 資料庫設計（Database / Schema Design）

在目前的 GHG 系統裡，我有參與資料表設計。

通常會先從業務邏輯定義 entity，例如排放來源或排放數據，再設計資料表之間的關聯。

同時也會考慮資料正規化，以及針對常用查詢欄位建立 index 來提升查詢效率。

---

# 7. 資料處理流程（Batch / Data Processing）

如果資料量比較大，我們通常會設計資料處理流程，例如：

1. 從 ESG Data Platform 取得資料
2. 進行資料轉換與整理
3. 再寫入 GHG 系統資料庫

這樣可以確保資料格式一致，也比較容易維護整體流程。

# 10. 心態提醒

這次聊天通常不是正式技術面試。

主管通常只是想了解：

- 溝通是否順暢
- 思路是否清楚
- 是否適合團隊合作

保持輕鬆，像專業交流聊天即可。
