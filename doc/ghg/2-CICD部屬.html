1. 功能簡述

GHG 後端採用 Jenkins Pipeline 自動化 CI/CD 流程，涵蓋：單元測試、打 Tag、Build 打包、Docker Image 產生、Helm Chart 發佈、自動部署。

GHG 系統架構 & DevOps CICD 流程

Git Branch Policy

  • Git Branch Policy:

    • develop: Dev 環境版本

    • feature/xxx: 功能開發分支

    • release/1.0: Test 環境版本

    • hotfix/1.0.1: Prod/Staging 緊急修正分支

    • feature/xxx -> develop: 功能開發完成後，合併到 develop 分支，自動部屬到 Dev 環境

    • develop -> release/1.0: release 1.0 版本開發完畢，合併到 release 分支，準備部署到 Test 環境

    • fix/XXXX -> release/1.0 -> develop: 修正 release 1.0 版本的問題，合併到 release 分支，準備部署到 Test 環境，並且合併到 develop 分支

      • v1.0.0-beta1: release branch 會自動打上 beta tag，會執行 CI (Build -> Push Image)，TL 手動執行 Jenkins CD Pipeline，過版到 Test 環境

      • v1.0.0-rc1: release/1.0 測試到一個段落，準備上到 Staging 環境，TL 手動打上 rc tag，系統就不會再自動打上 beta tag，會執行 CI (Build -> Push Image)，TL 手動執行 Jenkins CD Pipeline，過版到 Test / Staging 環境

      • v1.0.0: release/1.0 Staging 測試完畢，準備上到 Prod 環境，定版 v1.0.0，SRE 上線到 Prod 環境，後續該版要修復，必須走 Hotfix 流程

    • hotfix/1.0.1 -> release/1.0 -> develop: Hotfix 分支，修正 Prod / Staging 環境的問題，合併到 release 分支，準備部署到 Test 環境，並且合併到 develop 分支

      • v1.0.1: Hotfix 版本，SRE 上線到 Prod 環境
