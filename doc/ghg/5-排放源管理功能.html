排放源管理

所屬模組：adapter-rest / application 最後更新：2026-03-03

1. 功能簡述

排放源管理 GHG 碳盤查的核心數據功能：

  • 排放源 CRUD：新增、查詢、更新、刪除 排放源

  • Scope 查詢 : 取得 Scope 範疇資料

  • 活動數據管理：填寫排放源的活動數據

  • 排放源複製：從現有範疇複製排放源 or 過往的年度複製排放源

  • Excel 匯入：批量匯入排放源資料、活動數據資料

  • 運輸工具下拉:新增、查詢、更新、刪除 運輸下拉選單

EmissionSourceService（排放源查詢）

負責排放源資料的查詢與組合：

xxxxxxxxxx
getEmissionSourceById(id)
  → 查詢 EmissionSourceMain
  → 查詢 EmissionSourceExtension（Row Base）
  → 組合據點資訊、係數資訊、冷媒設備資訊
  → 組合活動數據清單
  → 設定佐證資料
  → 回傳 EmissionSourceWithActivityDataDto


getEmissionSourceListByIdListAndDate(idList, startDate, endDate)
  → 批次查詢排放源
  → 設定總和活動數據（依時間區間切割計算每日活動數據量）
  → 回傳 EmissionSourceDto List

Enrich 資料來源：據點資訊、係數資訊、冷媒設備資訊、運輸工具、佐證資料、指派填寫人員

排放源 查詢

  • 排放源查詢 Service 統一放在 EmissionSourceService

  • 最核心的兩個取得排放源資料 Function 取得單筆排放源:getEmissionSourceById、取得多筆排放源:getEmissionSourceListByIdListAndDate

  • 包含各種排放源資訊 enrich，都是先查出 Map 資料，再組回 EmissionSourceDto e.g., 據點資訊、係數資訊、冷媒設備資訊、總和活動數據、佐證資料、...

  • 在後端內 都是用 EmissionSourceDto 在各個 Service 間互相使用 e.g., 匯出清冊取得排放源、匯出報告書取得排放源、...

  • 回覆給前端的 會在 adapter-rest Controller層，透過 Converter 轉換回 Response 物件，只留下前端需要的欄位，多於欄位會省略

  • Extension 額外資訊會在 adatper-rest Controller層，透過 Converter 轉成固定的欄位

  • getEmissionSourceListByIdListAndDate 在設定總和活動數據 setTotalActivityData 會針對活動數據起訖日，切齊傳入的時間區間 (計算到每日活動數據)

排放源 / 活動數據 Extension

  • 依照不同的排放源/活動數據類型，會有不同的額外資訊欄位

  • EmissionSourceExtensionType、ActivityDataExtensionType 定義有哪些額外資訊欄位

  • 存入 EmissionSourceExtension、ActivityDataExtension 以 Row Base 設計，一筆排放源/活動數據 會對應到多筆 Extension

  • 在 adatper-rest Controller層，透過 Converter 轉成固定的欄位，回傳給前端

  • IEmissionSourceVoConverter convertExtensionToMap 前端傳入的 ExtensionVo to Row Base Map、convertExtensionToVo 後端的 Row Base Map to 回傳給前端的 ExtensionVo

ISO / GHG Scope 轉換

  • DB 以 ISO Scope 為主

  • 在 Service層 透過 ScopeCodeMapping 轉換對應的 GHG Protocol Scope

EmissionSourceEditService（排放源編輯）

負責排放源的新增/更新/刪除：

xxxxxxxxxx
createEmissionSourceList(siteId, annual, emissionSourceDtoList)
  → 驗證排放源資料（名稱唯一、必填欄位、係數存在等）
  → executeCreateEmissionSource() 執行新增


importEmissionSourceList(siteId, annual, emissionSourceDtoList)
  → Excel 匯入專用驗證（收集所有錯誤）
  → executeCreateEmissionSource() 執行新增


executeCreateEmissionSource()
  → 寫入 EmissionSourceMain
  → 攤平儲存 EmissionSourceExtension
  → 更新係數選擇紀錄 coefRecordService.saveCoefRecordByEmissionSourceList()
  → 指派填寫人員
  → 建立佐證資料檔案關聯


copyEmissionSourceListToAnnual(idList, targetAnnual)
  → 複製排放源到指定年度
  → 複製 Extension、指派填寫人員

排放源 新/刪/修

  • 排放源新/刪/修 Service 統一放在 EmissionSourceEditService

  • 新/刪/修 Function 都使支援多筆 idList

  • 新增排放源 createEmissionSourceList 匯入排放源 importEmissionSourceList 有各自的檢核 function，驗證通過後，執行新增是共用 function executeCreateEmissionSource

  • 執行新增/更新 流程: 寫入 EmissionSourceMain → Extension 設定 FkEmissionSourceId 攤平存入 → 更新係屬選擇紀錄 coefRecordService.saveCoefRecordByEmissionSourceList → 指派填寫人員 → 建立排放源佐證資料檔案關聯

  • 執行完新增/刪除/修改 在 adatper-rest Controller層 流程: 重新檢核更新 資料完整狀態 → (非同步) 重新計算 據點二氧化碳排放量總表

排放源複製

  • 跨年度複製：從過往年度複製排放源

  • 跨年度複製 是獨立的 API & 業務邏輯 copyEmissionSourceListToAnnual

  • 依照 Id 複製排放源、排放源 Extension、指派填寫人員

  • 同年度複製：從同據點的其他範疇複製排放源結構

  • 同年度複製 一樣是走一般的新增排放源流程，但多帶 copyFromId 欄位，建立排放源時，最後會複製活動數據資訊到新增的排放源

  • Scope 1/2 可複製到 Scope 3（4.2 燃料與能源）

  • ISO 2.1 電力僅允許特定類型（GREY, ONGRID_PPA, OFFGRID_PPA, GREEN_PROD）複製

EmissionSourceStatusService（狀態管理）

負責排放源與活動數據的完整狀態檢核：

xxxxxxxxxx
recheckEmissionSourceReadyStatus(emissionSourceId)
  → 取得 EmissionSourceWithActivityDataDto
  → 檢核排放源本身完整狀態（不含活動數據）
  → 逐筆檢核活動數據完整狀態（單位轉換、必填欄位等）
  → 更新 EmissionSourceMain.readyStatus
  → 更新 ActivityDataMain.readyStatus

狀態類型：

  • EmissionSourceReadyStatus：COMPLETE / ACTIVITY_DATA_INCOMPLETE / EMISSION_SOURCE_INCOMPLETE / COEF_UNASSIGNED / SCOPE_UNASSIGNED

  • ActivityDataReadyStatus：COMPLETE / UNIT_UNMATCHED / EMISSION_SOURCE_INCOMPLETE / COEF_UNASSIGNED

排放源完成狀態

  • 排放源完成狀態 Service 統一放在 EmissionSourceStatusService

  • 排放源 / 活動數據 的資料完整狀態 儲存在 DB EmissionSourceMain ActivityDataMain

  • 主要是 recheckEmissionSourceReadyStatus 重新檢核並更新 排放源 與 活動數據 資料完整狀態
