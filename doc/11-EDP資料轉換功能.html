EDP 資料轉換功能（edp-custom）

所屬模組：edp-custom（adapter-rest / application） 最後更新：2026-03-04

1. 功能簡述

edp-custom 是獨立的資料轉換微服務，負責將 EDP (ESG Data Platform) 的問卷填答原始資料（Raw Data）轉換為 GHG 系統所需的格式，並透過 GHG API 匯入 (GHG OpenAPI)。

整體流程由 Spring Batch Job 驅動，搭配 Airbyte 作為 EDP → DB 的資料同步工具：

  • Airbyte 負責將 EDP 資料 (IT SQL Server) 同步至 Raw Data DB (DSPBD PostgreSQL)

  • Spring Batch Job 讀取 Raw Data，進行題目分群、排放源轉換，寫入暫存表

  • 比對暫存表與主表差異（CREATE / UPDATE / DELETE），再呼叫 GHG API 匯入

  • 目前同步資料如果沒有指定的話，都是撈取系統年份近兩年的資料 (例如 2026年 會撈取 2025、2026 年資料進行同步)

觸發方式：

  • 排程觸發：CronJob 定期觸發 GET /api/v2/batch/edp-to-ghg-job，目前只有專案版正式環境每天7:30執行一次

  • API 觸發：系統呼叫 POST /api/v2/batch/sync-edp-by-site 觸發指定據點同步，由使用者手動觸發

Step 1：AirbyteSyncBarrierTasklet（Airbyte 同步等待屏障）

透過 Leader/Follower 模式 避免多個 Job 同時觸發重複同步：

xxxxxxxxxx
執行 AirbyteSyncBarrierStep
  → 查詢 AirbyteSyncWindow 狀態
  → 若非 RUNNING 且在 Cooldown 時間內已成功同步 → 跳過此 Step
  → 嘗試 tryStart：
      ├── 成功（Leader）：

SyncSystemErrorEmail（系統異常通知）

ReadReportAndGroupQuestionsListener.afterJob() 會對每一個 Failure Exception 獨立判斷類型發出 Email。

SyncDataErrorEmail（資料異常通知）

兩種資料異常可同時發生，此時同一封 Email 會同時包含 siteErrorMessage 與 emissionSourceErrorMessage 兩個錯誤欄位。

6. 擴充指引

新增 Scope 類型轉換 或 新增資料轉換邏輯

  1. 在 TransferScopeType Enum 新增 Scope 類型定義

  2. 實作 ITransferScopeService，建立 TransferScopeXxxService

    • 實作 getTransferScopeType()

    • 實作 rawDataGroupToEdpMain()（Raw Data → EdpCustomMain）

    • 實作 edpMainToEmissionSourceExtension() / edpMainToActivityDataExtension()（GHG 額外資訊）

  3. TransferScopeFactory 會在 @PostConstruct 自動掃描並註冊，無需手動修改

  4. RawDataGroupType 新增 分群後判斷類型 (資料分群類型 對應 TransferScopeType)

EDP 調整 下拉選單選項

  1. 檢查 TranferScopeXxxService 中是否有對應的下拉選單轉換邏輯（例如 Scope 1.4 冷媒類型）

  2. 若只是調整項目名稱、擴充項目選項，更新 edpCustomDataMap 資料表即可（Key 對應 EDP Raw Data DB 的 TopicDropdown 表中的 key，Value 對應 GHG 系統的資料）

新增 Batch Job Step

  1. 在 BatchConfig 建立新的 @Bean Step

  2. 在 readReportAndGroupQuestionsJob() 的 .next() 串入新 Step

  3. 若需要 Tasklet，建立新的 XxxTasklet implements Tasklet

新增異常通知 Email 類型

  1. 建立新的 XxxEmailParameter extends AbstractEmailParameter

  2. 在 EmailService 新增發送方法

  3. 建立對應的 HTML 模板（TW / EN）

  4. 在對應新的異常情境捕捉到的地方呼叫 EmailService.sendXxxEmail()

匯入後的後處理流程

ImportDataController 在呼叫 importDataApiService.importData() 成功後，還會執行以下後處理（失敗不影響主流程，僅記錄 ImportStatus）：

xxxxxxxxxx
importData()
  → 清除 Entity Cache
  → emissionSourceEditService.updateEmissionSourceCoef()   ← 依係數推薦設定係數資訊
  → emissionSourceStatusService.recheckEmissionSourceReadyStatus()  ← 重新檢核排放源資料完整狀態
  → activityDataRatioService.setAdRatioByEmissionSource()  ← 設定活動數據公司分配比例
  → activityDataSummaryService.setAdSummaryByEmissionSource() ← 更新活動數據總表
  → (非同步) companySiteCo2EmissionService.resetSiteCo2EmissionSummary() ← 重新計算據點 CO₂ 排放當量

ImportStatus 說明

import_data_log 匯入紀錄

每次呼叫 POST /oapi/v2/import-data/api-format 時，ImportDataController 都會透過 ImportDataLogService.createImportDataLogFromAPI() 在 GHG 主 DB 的 import_data_log 資料表中建立一筆匯入紀錄，記錄本次 API 匯入的完整資訊。

排放源 / 活動數據 回溯：emission_source_main 與 activity_data_main 兩張資料表均有 fk_import_data_log_id 欄位，記錄該筆資料是由哪一次匯入所建立或更新，可透過此欄位追溯到對應的 import_data_log 紀錄。
