1. 功能簡述

GHG 平台採用 RBAC 進行權限管理：

  • 功能權限：控制可操作的資源與動作 (API)

  • 資料權限：控制可存取的資料範圍（哪些據點/排放源）

  • 人員指派：指派據點管理員、填寫人員

  • 通知信件：指派任務後發送通知 Email

CatalogService（功能清單）

負責依角色動態回傳可使用的功能項目：

xxxxxxxxxx
getRootCatalogList()
  → 若為 Admin → 回傳所有 ROOT 類型功能清單
  → 取得使用者的所有角色
  → 依角色查詢 CatalogRoleMapping 對應的功能 Code

  → 回傳 CatalogNodeDto List

  → 若為 Admin → 回傳所有 SITE 類型功能清單
  → 判斷使用者對該據點的角色（SO / DE）
  → 依角色查詢對應的功能清單
  → 回傳 CatalogNodeDto List

資料結構：

AssignTaskService（任務指派）

負責任務指派的核心邏輯：

xxxxxxxxxx
getUserTaskList() 取得 user 被指派的任務, 角色詳細資訊
  → 取得當前使用者
  → 查詢使用者的所有任務（RbacTask）
  → 依角色分群（ADMIN / SO / DE）
  → 回傳 UserTaskDto List


assignTaskList(resource, targetId, taskDtoList) 指派任務, 比較既有任務與新任務, 只對需要變更的部分進行處理
  → 取得既有任務 By Resource & TargetId
  → 比較新舊任務清單
  → 找出需要刪除的任務（存在舊、不存在新）
  → 找出需要新增的任務（存在新、不存在舊）
  → 執行刪除/新增
  → 回傳新增的任務清單（用於發送通知）


sendSiteAssignmentEmail(addedTasks, siteMap) 發送指 派據點管理員任務的通知郵件
  → 依 targetId 分群任務
  → 收集新指派的使用者們
  → 判斷指派者角色（Admin / SO）
  → 呼叫 EmailService 發送通知


sendEmissionSourceAssignmentEmail(addedTasks, emissionSourceMap) 發送指派 填寫人員任務的通知郵件
  → 依 targetId 分群任務
  → 收集新指派的使用者們
  → 判斷指派者角色（Admin / SO / DE）
  → 呼叫 EmailService 發送通知

角色判斷邏輯：

  • rbacAuthorizeService.isSystemAdmin() → Admin

  • 據點 ID 在被指派清單中 → 據點管理員 (SO)

  • 排放源 ID 在被指派清單中 → 填寫人員 (DE)

指派流程

xxxxxxxxxx
Admin 指派 SO
  → POST /api/v2/rbac-task/site/{siteId}
  → 建立 RbacTask（userId, roleId=SO, resource=SITE, targetId=siteId）
  → 發送 SiteAssignment Email


Admin/SO 指派 DE
  → POST /api/v2/rbac-task/emission/{emissionId}
  → 建立 RbacTask（userId, roleId=DE, resource=EMISSION_SOURCE, targetId=emissionId）
  → 發送 EmissionAssignment Email

RuleHandler 執行流程

xxxxxxxxxx
API Request → AOP 攔截 @RuleAuthorize
  → 注入對應 RuleHandler Bean (可掛多個 RuleHandler，設定 isAllGranted 決定是否需要全部通過)
  → handler.isGranted(parameters)
    ├── 從 parameters 取得 resource、targetId
    ├── 從傳入的參數中取出 targetId 實際的值 (如：siteId、emissionId)
    ├── 查詢使用者的 RbacTask 表
    ├── 取得 Resource 對應的 targetId 列表
    ├── 檢查 targetId 是否在允許範圍
    └── 不通過 → 403 Forbidden

6. 擴充指引

新增資源類型

  1. 在 GHGRbacResource Enum 新增資源定義

  2. 在 RbacConfig 確認資源已註冊

  3. 在 Controller 加上 @RbacAuthorize 註解，設定新的 Resource

  4. 在 DB 設定 RbacPermissionRepository 新增 Resource 的 CRUD 權限

  5. 在 DB 設定 RbacRolePermissionMapRepository 對應角色新增權限

新增動作類型

  1. 在 GHGRbacAction Enum 新增動作定義

  2. 在 DB 設定 RbacPermissionRepository 新增 Action 的 CRUD 權限

  3. 在 DB 設定 RbacRolePermissionMapRepository 對應角色新增權限

新增角色

  1. 在 GHGRbacRole Enum 新增角色定義

  2. 在 DB 設定 RbacRoleRepository 新增角色資料

  3. 在 DB 設定 RbacRolePermissionMapRepository 對應角色新增權限

  4. 在 CatalogService 新增角色對應的功能清單邏輯

  5. 檢查 RuleHandler 是否需要新增對應角色的檢核邏輯 (照理來說 RbacAuthorize 不需要修改，但 RuleHandler 可能會有角色判斷的邏輯需要新增)

  6. 檢查 AssignTaskService 是否需要新增對應角色的指派邏輯

新增 RuleHandler

  1. 實作 IRuleHandler 介面

  2. 實作 isGranted(Map<String, Object> parameters) 方法

  3. 在 Controller 加上 @RuleAuthorize(ruleHandler = XxxRuleHandler.class)

新增郵件通知類型

  1. 建立新的 XxxParameter extends AbstractEmailParameter

  2. 在 EmailParameterBuilder 新增 static method 建構參數物件

  3. 建立對應的 HTML 模板（TW / EN）

  4. 在 EmailService 新增發送方法

新增指派類型

  1. 在 GHGRbacResource 新增指派資源（如 XXX_OWNER）

  2. 在 RbacAssignController 新增指派 API

  3. 在 AssignTaskService 新增發送通知邏輯
