活動數據管理

所屬模組：adapter-rest / application 最後更新：2026-04-21

1. 功能簡述

活動數據管理是 GHG 碳盤查中，承接排放源後續填報與計算的核心功能：

  • 活動數據 CRUD：新增、查詢、更新、刪除 活動數據

  • 活動數據完整性檢核：必填欄位、起訖日邏輯、單位可轉換性、狀態更新

  • 活動數據自動計算：依不同 Scope / 類別進行活動數據與 CO2e 計算

  • 活動數據 Extension 管理：依排放源類型存取額外欄位（Row Base）

  • 活動數據攤平總表：依起訖日攤平每日數據，供報表 / 清冊 / 彙總使用

  • Excel 匯入串接：模板下載、匯入驗證、錯誤回饋

  • 台灣高鐵碳排放計算：3.3 / 3.4 / 3.5 類別支援站對站碳排自動帶入計算

ActivityDataService（活動數據）

負責活動數據 CRUD、計算、驗證：

xxxxxxxxxx
getActivityDataById(id)
  → 查詢 ActivityDataMain
  → 查詢 ActivityDataExtension（Row Base）
  → 設定佐證資料
  → 回傳 ActivityDataDto


updateActivityDataList(emissionSourceId, activityDataList)
  → 驗證必填欄位（日期、起訖日、活動數據、單位）
  → 驗證日期邏輯（startDate <= endDate）
  → 依類別計算活動數據
    ├── 一般情境：前端直接提供 activityData & activityUnit
    ├── 台灣高鐵情境（3.3 / 3.4 / 3.5）：
    │    ├── 3.3：unitCarbonEmission × commutingDays
    │    └── 3.4 / 3.5：unitCarbonEmission × passengerCount
    └── 一般運輸情境（3.1 / 3.2）：貨物重量 × 運送距離
  → 計算二氧化碳當量（7 gas / CO2e）
  → 儲存 ActivityDataMain / Extension
  → 更新分配比例 & 攤平總表


checkActivityDataReadyStatus(activityDataDto)
  → 檢核活動數據完整狀態（單位可轉換、必填欄位等）

台灣高鐵計算邏輯補充

  • 排放源類別為 3.3 / 3.4 / 3.5 且排放源 Extension 的運輸工具設定為「台灣高鐵」時，啟用站對站碳排計算

  • 前端帶入 unitCarbonEmission（站對站碳排量，單位 kgCO2e）

  • 3.3 通勤：activityData = unitCarbonEmission × commutingDays

  • 3.4 / 3.5 商旅/客訪：activityData = unitCarbonEmission × passengerCount

  • 若起訖站相同，unitCarbonEmission 回傳 0

  • 前端限制：運輸工具已設定台灣高鐵後，前端阻擋使用者修改運輸工具，避免資料不一致

6. 擴充指引

新增活動數據延伸欄位

  1. 在 ActivityDataExtensionType 新增欄位定義

  2. 在 adapter-rest Converter 增加 VO ↔ Map 轉換邏輯

  3. 在 ActivityDataService 增加驗證與計算邏輯

  4. 視需要更新 Excel 匯入模板解析與驗證規則

新增類別計算邏輯（如新運輸場景）

  1. 先定義適用 Scope Code（ISO / GHG）

  2. 在 ActivityDataService 增加分類判斷與計算公式

  3. 補上 Extension 欄位取值與 null-safe 處理

  4. 更新 readyStatus 檢核規則

  5. 加上單元測試與整合測試（含 Excel 匯入情境）

調整 Excel 匯入欄位規則

  1. 更新對應 Sheet Parser 與欄位 Enum

  2. 同步更新驗證規則（必填 / 下拉值 / 日期）

  3. 更新錯誤訊息 key 與 i18n 文案

  4. 確認 DTO 組裝與後續計算流程不受影響

更新台灣高鐵碳排放年度資料

  1. 在 thsr_carbon_emission 表新增指定年度的站對站資料（僅存單向，共 66 筆）

  2. 資料單位為 kgCO2e

  3. 未來若年度碳排數值有更新，新增年度資料列而非覆蓋，保留歷史資料

7. 交接建議（維運重點）

  • 活動數據是「計算入口」，任何欄位異動需同時檢查：

    • CRUD DTO

    • Extension Mapping

    • Excel 匯入解析與驗證

    • readyStatus 檢核

    • summary 重算

  • 台灣高鐵計算需注意 3.3 與 3.4 / 3.5 的乘數欄位不同（commutingDays vs passengerCount），不可混用

  • 排查數值差異時，優先看：

    1. 主表值是否正確落庫

    2. Extension 是否存在且 key 正確

    3. 係數與單位轉換是否命中

    4. summary 是否已重算

  • Excel 匯入未來待辦（台灣高鐵相關）：

    • 當排放源類別為 3.3 / 3.4 / 3.5 且運輸工具為台灣高鐵時，需透過出發地址 / 目的地址反查站名 Key，自動帶入 unitCarbonEmission
